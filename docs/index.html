Open specification · policy as code · Apache-2.0

AI writes the code. Your policy decides what merges.

ODS reads the attribution AI tools already leave (Co-Authored-By and Assisted-by trailers, git-ai notes, PR disclosure), combines it with your scanners' findings and any AI reviewer's verdict, and renders one auditable PASS, WARN or BLOCK on every pull request. No forms, no tagging, no black box.

Get started in 5 minutes → Read the specification
$ go install github.com/open-delivery-spec/cli/cmd/ods@latest

Or add open-delivery-spec/validate-action@v1 to a workflow: it runs on every PR with no configuration.

How it works

Four stages, each with a published contract.

Every stage writes a versioned JSON document, so any pipeline can produce or consume it, and the policy decides on facts rather than on a black box.

Detect

Which changes are AI-assisted, from the signals the tools volunteer: trailers, git-ai notes, PR disclosure, branch prefixes. Confidence is capped at 95%.

$ ods detect
detect-output/v1

Analyze

What the built-in heuristics flag, plus every finding your scanners already produce, imported as SARIF (Semgrep, CodeQL, golangci-lint).

$ ods analyze --sarif
analyze-output/v1

Score

How much technical debt the change adds, driven by quality. AI share only amplifies real findings: a clean, fully AI-written change scores about zero.

$ ods score
score-output/v1

Check

Your policy, in Rego, over one input document: attribution, findings, coverage, risky paths and any AI reviewer's verdict.

$ ods check
policy-input/v1 → check-output/v1
Result on the pull request: PASS WARN BLOCK plus a review tier, a PR comment and a machine-readable report.

The decision

One gate. Deterministic findings may block; AI opinions may only ask for more review.

Reviewers, scanners and humans all feed the same gate. Whatever an LLM says, it can raise the bar for a change but never wave one through on its own.

PASS

No rule fired

Merge as usual. A pass means your policy found nothing, not that the code is proven correct.

WARN

Look before merging

Undisclosed AI use, source without tests, a sensitive path touched. The PR comment says why.

BLOCK

The job fails

A deny rule matched, such as a critical finding. With a required check, the merge button stays grey.

Review routing auto mechanically safe standard normal review elevated a maintainer should look

Specification first

A contract anyone can implement, and tools that implement it.

The JSON Schemas and the conformance suite are the specification. The CLI and the GitHub Action are one implementation of it, not the only one allowed.

The specification

Versioned contracts between the stages, and the files a repository keeps.

  • policy-input/v1The one document a policy reads.
  • check-output/v1Allowed, denials, warnings, review tier.
  • review-verdict/v1How any AI reviewer's opinion enters the gate.
  • .ods/Where the policy lives in a repository.
  • conformance/Scenarios every implementation must pass.

Reference tooling

Open source, single binary, runs in any CI that can run a program.

  • odsThe CLI: detect, analyze, score, check.
  • validate-actionAll four stages on every PR, with a comment.
  • ods reportAI share over history, per repo or organization.
  • ods attestAI-code evidence as a CycloneDX 1.6 document.
  • org-ai-reportA scheduled dashboard across every repository.

Honest by design

It governs the AI you can see, and says so.

Detectors that claim to spot AI-written code also flag careful humans. ODS does not pretend to. It reads what tools disclose and keeps its claims inside what that evidence supports.

Attribution, not forensics

The primary signal is the trailer the tool writes. Stripping it evades ODS; diff heuristics are only a low-confidence fallback, and never certainty.

A signal producer, not an oracle

ODS never says code is correct. It reports facts, scores them, and lets your policy decide, with every input on the record.

Humans where they matter

The aim is not merging without people. It is freeing them from the changes that are mechanically safe and pointing them at the ones that are not.
